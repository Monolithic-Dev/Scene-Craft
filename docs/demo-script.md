# SceneCraft — Demo Script (3-minute recording)

Follows the timing budget in [`docs/Phases/PHASE-07-DEMO-AND-SUBMISSION.md`](Phases/PHASE-07-DEMO-AND-SUBMISSION.md) §4. **Record against the real deployed staging/production environment, not localhost** — see that doc's Common Pitfall #1. Use a real multi-scene script (a page or two, several characters, at least one location/time-of-day change) — a one-line toy script undersells the Breakdown Agent.

Captions/subtitles required in English even if narration is already English — don't skip burning them in or uploading an `.srt`.

| Time | Segment | What's on screen | What to say (adapt to your voice, keep the beats) |
|---|---|---|---|
| 0:00–0:15 | **Hook** | A blank script page / cursor blinking in a text editor | "This is every indie director's starting point — a script, and no way to show anyone what it looks like. SceneCraft turns this into a working app in the time it takes to get coffee." |
| 0:15–0:45 | **Upload → Breakdown** | Real script upload on the SceneCraft dashboard; cut to the live agent-trace panel as it lights up | "I upload the real script — no toy example. Watch the trace panel: the Breakdown Agent is reading it right now, live, turning prose into structured scenes and shots." |
| 0:45–1:15 | **Frames** | Storyboard frames appearing in the trace panel / project view, panning across a few to show style consistency | "Each shot gets its own storyboard frame, generated by Gemini on Vertex AI — and notice the visual style stays consistent scene to scene, because every frame shares the same locked style reference." |
| 1:15–2:00 | **App-Build (centerpiece)** | Trace panel showing App-Build then Critic running; cut to a click-through of the live previs app on its hosted URL | "Now the App-Build Agent assembles all of that into a real, clickable previs app — and the Critic Agent independently checks its work before it's ever shown as done. This isn't a mockup — it's live, right now, at this URL." (click through 2-3 shots, show the scene navigator) |

## Recording checklist (before you hit record)

- [ ] Rehearsed once against the actual deployed URL, not localhost
- [ ] Real script loaded and ready (not typed live — upload should be instant, not a live-typing distraction)
- [ ] Trace panel visible and confirmed working (Firestore live push, not degraded to polling) — refresh the page once beforehand to confirm
- [ ] Gemini quota checked (`GEMINI_API_KEY`'s 20/day free-tier cap — see README) — don't burn it on rehearsal takes right before the real recording
- [ ] Screen resolution/zoom set so trace panel text and the previs app are both legibly readable in the final video
- [ ] Captions burned in or `.srt` uploaded alongside
- [ ] Uploaded to YouTube or Vimeo, set to public (not unlisted-only if the form requires public), link tested from a logged-out browser

## If a step is slow on camera

Per the phase doc: either genuinely wait it out with a brief voiceover explaining what's happening, or use a clearly-labeled speed-up cut (a visible "2x" or "sped up" marker) — never a silent hard cut that pretends to be real-time. The rules require the video to show the product actually functioning.
